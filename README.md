# 群文件管理（astrbot_plugin_groupfile_console）

为 AstrBot + SnowLuma/NapCat（OneBot 11）设计的群文件自动维护插件：规则分类、定时整理流水线、时效清理、容量播报、WebUI 控制台。
- **维护配置导出/导入**：「定时与维护」页顶部 📤/📥 按钮——只含 定时整理 / 容量提醒 / 时效清理 / 查重 四块（不动规则和管理员），方便多群复制或备份；v2.1.2 起完整导出（此前缺时效与查重）

## 核心特性

- **规则自动分类**：关键词 / 构建器 / 正则三种规则，按具体度评分取最优命中；**文件类型限定内置 130+ 种**（漫画 `cbz/cbr/cb7/cbt`、电子书、文档、音视频、代码、设计稿等，也可自定义任意扩展名）；**匹配内容留空 + 限定类型 = 按类型兜底**（如所有 `cbz/cbr` 自动进「漫画」，且优先于完全不限的兜底规则）；支持**排除词**（文件名含排除词时该规则不生效）、**单条停用**（不删除随时恢复）；WebUI「**试一试**」贴文件名即时看会命中哪条、原因是什么；「**预览整理**」先看谁会被移动到哪再决定跑不跑；目标文件夹缺失自动创建并提醒
- **定时整理流水线**：每群独立 cron（可多时间点），到点执行「分类移动 → 时效清理 → 容量检查」并汇总为一条报告；全部无动作时保持静默
- **时效清理（按时间分文件夹）**：按文件的上传/修改时间计算年龄，超龄自动处理——群级默认天数 + 文件夹级覆盖（如 temp 7 天、HV2 90 天），动作分「只报告 / 移入回收文件夹 / 直接删除」三级，回收文件夹自动创建；回收站内文件不再二次扫描
- **容量播报**：跟随定时任务顺带检查（边界触发：未超→超才提醒，且每日最多一次，防刷屏）
- **WebUI 控制台**：AstrBot 面板 → 插件 → 群文件管理，六个分页（总览 / 群配置 / 分类规则 / 定时与维护 / 文件管理 / 帮助），纯点击管理，保存即生效；**规则卡片默认收起**（只留头部与一行匹配摘要，可单条展开或一键全部展开/收起），**快捷模板**一键建漫画/电子书等规则，**扫描结果按文件夹折叠**；规则有改动时显示"● 未保存"，切群/重新加载/关页面会提醒；支持**把当前群规则复制到其他群**（合并或覆盖）；**文件类型按分组标签切换、单面板展示**，页面长度大幅收紧；**文件管理页支持按类型多选筛选**（按群记住上次选择），文件图标按类型着色；**群配置为勾选式**——自动列出机器人所在群，勾选=启用本插件、取消=停用（配置保留），支持搜索与成员数展示；**管理员/群管理员支持头像卡片点选**（可搜索昵称/群名片/QQ号，跨群切换）；**定时与维护按群导航**（群 chips 切换 + 每个分区标题带群徽章，不怕多群混淆）；**主题跟随系统**（自动匹配操作系统深浅色并实时切换，无需手动设置）
- **命令极简**：v2.0 命令表精简为单字动词 + 短前缀 `/gf`；列表上下文（列/查后 5 分钟内直接用序号删/移）+ 统一两段确认
- **查重维护**：WebUI 查重扫描（同名归一策略：split / regex / smart / exact），两步确认删除
- **多群独立配置**：每群各自的规则、定时、时效、容量阈值、管理员；支持导入导出
- **零第三方依赖**

## 安装

1. 把整个 `astrbot_plugin_groupfile_console` 文件夹放入 AstrBot 的 `data/plugins/` 目录
2. 重启 AstrBot（或面板里重载插件）
3. 插件 → 群文件管理 → 控制台：添加群、配置规则与流水线

> 更新：AstrBot 无法覆盖同名插件目录，需先在插件页卸载再装新包（配置数据保留在插件数据目录，升级不丢）。
>
> v1.x → v2.0 是破坏性变更：命令表精简为 `/gf` 单字动词，设置类命令改走 WebUI；常用旧命令名（列表/删除/移动/诊断/整理等）保留为兼容别名，直接照旧输入也能用。v2.0.1 起新增文件夹名模糊匹配与空参/错误输入的用法提示；v2.0.3 重做规则编辑器（目标文件夹下拉防丢值、限定类型折叠显示已选摘要、勾选框对齐）。群配置数据完全兼容，无需迁移。

## 指令（/gf = /群文件）

```
/gf                     # 前缀
/gf 状态                 # 空间/整理/时效/规则一览
/gf 列 [文件夹名]         # 列根目录或文件夹内文件（结果带序号）
/gf 查 <关键词> [序号]    # 递归搜索；带序号=把该文件发到群
/gf 删 <序号|范围|全部>    # 删最近一次 列/查 的文件（两段确认）
/gf 删 <文件夹> <序号|全部>
/gf 移 <序号|关键词> <目标文件夹>
/gf 建 <文件夹名>
/gf 整                   # 立即跑流水线：分类 → 时效 → 容量，出报告
/gf 开 | /gf 关          # 本群启停
/gf 绑 [备注名] | /gf 解   # 绑定/解绑群（解绑两段确认）
/gf 管 @某人 | /gf 管 删 @某人
/gf 诊断                 # 自查报告
/gf 确认 | /gf 取消       # 危险操作统一两段确认（60 秒内有效）
```

- 群内使用默认管当前群；私聊需带群号（如 `/gf 状态 123456`）
- **按格式找文件**：`/gf 查 cbz`、`/gf 查 epub`（扩展名也参与关键词匹配，可直接搜漫画/电子书格式）
- **旧命令名兼容**：列表/删除/移动/建文件夹/整理/清理/启用/停用/绑定/解绑/管理员/诊断/搜/容量 等 v1 命令名全部保留为别名，肌肉记忆直接用
- **文件夹名自动匹配**：输入名称的一部分即可（`/gf 列 hv` 自动进 `HV2`；多匹配会列出候选；`移` 的目标唯一命中自动用现有文件夹，避免手滑建错）
- 只发 `/gf`（不带子命令）会显示全部指令说明（AstrBot 框架内置指令树）
- 管理员判定：AstrBot 管理员 → 全局管理员（WebUI/面板配置）→ 该群管理员
- 规则、定时、时效、容量线、查重模式等设置项全部走 WebUI 控制台

## 定时流水线说明

```
cron 到点
  ├─ 1. 分类移动：按规则表移动文件（已在目标文件夹的跳过）
  ├─ 2. 时效清理：扫描超龄文件（可分文件夹配置天数与动作）
  ├─ 3. 容量检查：超限才播报（边界触发 + 每日一次）
  └─ 汇总一条报告推送到群；全部无动作则静默
```

时效清理的文件年龄 = max(上传时间, 修改时间)；QQ 群文件接口没有「最后下载时间」，因此判定的是文件年龄而非热度。文件夹覆盖里天数填 0 表示该文件夹不参与时效清理。
**v2.7.0**：协议端没有返回上传/修改时间的文件视为「时间未知」，只报告、不回收不删除。

## 发送临时文件（v2.7.0）

`/gf 查 <关键词> <序号>` 与文件页「发到群」会先把群文件下载到本机，再用 `file://` 交给协议端。这个临时目录必须让协议端能读到：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 目录 | `temp/astrbot_plugin_groupfile_console/send_tmp` | 与协议端共享的 temp；插件配置 `deliver_dir` 或面板可覆盖 |
| 产物权限 | 目录 777 / 文件 666 | 防容器 umask 偏严造成 EACCES |
| 保留秒数 | 600 | 发送完成后延迟删除；面板「定时与维护 → 发送临时文件」可调 30–86400 |
| 残留清理 | 1 小时 | 启动清一次、运行中每 10 分钟一次；面板可调 1–168 小时 |
| 发送中保护 | 开 | 正在下载/发送的文件不会被清扫，最多重试 20 次 |
| 失败兜底 | 开 | 下载失败立即删；直发失败按 60 秒延迟清理，绝不永久残留 |

与群文件「老文件处理（TTL）」无关，不改 `auto_delete` 语义。

## 默认分类规则（每群可改）

| 来源 | 匹配（文件名） | 目标文件夹 |
| --- | --- | --- |
| jm | `^\d+_\d+` | HV2 |
| suwayomi | （空 = 兜底全部） | COS |

> 目标文件夹不存在时会自动创建；创建失败则在报告中列出缺失文件夹，手动建好后重新整理即可。
