## 三、批量编辑排版（不牺牲折叠卡）

在「群基础设置」里加**二级 chip**：

```
群基础设置
 ├─ 单个群    ← 原来的下拉 + 折叠卡（导出/导入/危险区）
 └─ 批量编辑  ← 群列表勾选 + 操作栏
```

批量区结构（自上而下）：

1. 说明行：「勾选多个群后，用下方批量操作一次应用（只改勾选的群）」+ 右侧「已选 N 个群」；
2. 群列表：每行 `[✓] 群名 （群号） …… 启用中 · 管理员 X 人 · 规则 Y 条`，`max-height 340px` 内部滚动，行距 8；
3. 操作栏（一行可换行）：`全选` · `启用选中` · `停用选中` · 管理员 QQ 输入 · `追加管理员` · `移除管理员` · 结果提示。

为什么不做成「多群并排卡片」：并排卡片在群数 >3 时要横向滚动，而且规则/定时子面板无法压缩进窄列。列表 + 操作栏在 2~20 个群都稳定。

批量只写 `enabled` / `admins` 两个基础字段；规则、定时、时效、查重仍在各自页签编辑，避免误改复杂配置。

## 四、实现

- `renderGroupsViews()` 同时渲染单群卡与批量列表；
- 批量提交逐群 `POST /groups`，成功后 `Object.assign` 本地对象，最后统一 `renderBatchList()` + `renderScopeList()`；
- 缓存 `window.__gfcAvailable` 复用「管理范围」的群列表，避免批量后再请求一次；
- 失败逐群计数，提示「完成：成功 N / 失败 M」。
