# groupfile_console v2.9.0 方案（精简 + 打磨 + 界面重排）

- 日期：2026-10-30
- 范围：`astrbot_plugin_groupfile_console`（03_群文件）
- 测试群：1128651283「新群测验」
- 上一版：v2.8.0（群运维级，功能加过头）

---

## 一、问题（用户反馈）

> 「回收站功能没有用删掉，新加的功能很多都是冗余的，我们插件本身的也要优化，还有界面布局要安排的比较合理间距比例这些都要考虑到」

拆成三件事：
1. 删掉 v2.8.0 里没人用的功能；
2. 优化插件本体（去冗余代码、收敛逻辑）；
3. 界面间距/比例重排。

## 二、删除清单（v2.8.0 新增 → v2.9.0 移除）

| 功能 | 处理 |
| --- | --- |
| 回收站（RecycleStore + `/gf 回收` `/gf 恢复` + 面板还原） | **删除**；TTL 的 recycle 动作（移入 `_回收` 文件夹）保留，只是不再记录索引 |
| 任务中心（TaskManager + 任务页 + 4 类后台任务） | **删除**；面板操作回到同步调用 |
| 容量趋势（TrendStore + 趋势图） | **删除** |
| 权限分级（view/move/delete/admin + 面板权限编辑） | **删除**；回到「管理员 QQ + 全局管理员」 |
| 规则优先级 priority | **删除**；回到「匹配内容越长越具体」 |
| 审计页 / 运维设置页 | **删除页面**；审计文件与 `/gf 审计` 命令保留 |

保留下来的 v2.8 内容都是修 bug 或低成本能力：按事件平台绑定、按群锁、时间归一、配置校验、扫描防护、TTL 删除上限、确认绑定用户+群、`/gf 列` 分页、`/gf 预览` 试运行、定时补跑。

## 三、本体优化

1. 删 `core/trend.py`，`core/ops.py` 只留 `AuditLog`（-约 200 行）。
2. 权限判断收敛成 `_is_admin_user`，命令与确认流程统一。
3. 配置去掉 `ops` 段与 `permissions`，`groups.json` version 4；旧 v3 读入自动忽略多余字段并回写。
4. 删 10 个已无用的 Web API 注册与实现（task/tasks/task_cancel/audit/ops/trend/recycle/recycle_restore/recycle_delete）。
5. pyflakes 全绿；单测 19+15+3+7=44 项通过。

## 四、界面重排（8px 体系）

新增变量：

```
--sp-1:4 --sp-2:8 --sp-3:12 --sp-4:16 --sp-5:24 --sp-6:32
--pad-page:24  --pad-card:16  --gap-card:16  --gap-ctl:8
--h-ctl:32  --h-ctl-sm:26
```

- 容器 `32px 24px 64px`；卡片 `16px 18px`，卡间距 16；
- 标题→内容 12px，工具栏 8px，表单栅格 `8×16`（列宽 180）；
- 按钮统一 32px 高（小 26），输入框 32px 高 + `6px 10px`；
- 导航 chips 4px；
- 修 `.section-header h2` 里失效的 `align-align:center`；
- 删重复 `.btn-sm` 与冲突的 `.toolbar{gap:10px}`。
